# Лабораторная работа 4

Тема: полная бизнес-логика ИС фотоцентра — частичное обновление, удаление, поиск и фильтрация. Стек: Node.js + Express + SQL Server, продолжение лабораторной №3.

## Что сделано

- `PATCH /api/services/{id}` изменяет только присланные поля.
- `DELETE /api/services/{id}` физически удаляет неиспользуемую услугу; 404 при отсутствии, 409 при наличии позиций заказа.
- `GET /api/services` принимает `search`, `min_price`, `max_price`, `type`.
- В Swagger добавлены параметры фильтрации, схема ServiceUpdate и PATCH.
- На странице «Услуги» добавлены поиск, тип, диапазон цен и сброс фильтров.
- Подготовлены отчёт, реальные скриншоты и протокол `lab4-verification.json`.

## Как открыть после закрытия чата

Из папки проекта выполните `npm run lab4`, затем откройте [Swagger](http://127.0.0.1:3001/docs/). SQL Server должен работать, а `.env` — содержать параметры подключения. Учебный запуск выбирает отдельную базу PhotoCenterLab12 из лабораторной №2. `npm run lab3` и `npm run lab4` теперь запускают один и тот же сервер; одновременно запускать их на порту 3001 не нужно.

В Swagger выполните `POST /api/auth/login` с `lab_ivanova` / `demo`. После перезапуска сервера войдите заново. Ручной ввод через Authorize не требуется.

Обычная страница услуг с фильтрами: [services.html](http://127.0.0.1:3001/services.html). Она использует ту же сессию и то же API.

## Что показать преподавателю

1. `GET /api/services`: в search впишите `фото`, min_price `10`, max_price `50`. Execute → 200, только подходящие услуги. Параметры можно применять по отдельности и вместе. Границы цены включаются.
2. Создайте свою временную услугу через POST:

```json
{"Название":"ЛР4 моя проверка","Тип":"Печать документов","Цена":25}
```

3. Запомните возвращённый `ID_Услуги`. В следующих шагах используйте только этот ID, а не идентификаторы исходных услуг.
4. `PATCH /api/services/{id}`: передайте только `{"Цена":35}` → 200. Название и тип останутся прежними. Повторите GET по этому ID, чтобы увидеть сохранённые данные.
5. Передайте `{"Цена":null}` или `{"Цена":-1}` → 422. Пустой объект `{}` и лишние поля тоже запрещены.
6. `DELETE /api/services/{id}` → 204 без тела ответа. Это успешное удаление.
7. Повторите корректный PATCH на тот же ID → 404, «Услуга не найдена».

На сохранённых скриншотах использована временная запись ID 11; она уже удалена. Для собственной демонстрации получите новый ID через POST.

## Как работает код

В `schemas/service.js` схема ServiceUpdate имеет необязательные поля; функция parseService вызывается с `partial: true`. Отсутствующее поле не попадает в набор изменений. Явное null запрещено, поскольку столбцы услуги в SQL имеют NOT NULL. Это отличается от очистки значения: «не прислать поле» и «прислать null» — разные действия.

В `repositories/services.js` PATCH собирает SET только из фиксированного списка Название, Тип, Цена и передаёт значения параметрами. Один UPDATE с OUTPUT INSERTED возвращает результат, а отсутствие строки преобразуется роутером в 404. Это исключает перезапись неприсланных полей устаревшими данными.

DELETE проверяет `rowsAffected`: 0 → 404, 1 → 204. Предварительный SELECT не обязателен: проверка результата удаления атомарно учитывает отсутствие объекта. Внешний ключ защищает используемые услуги; SQL Server 547 преобразуется в HTTP 409. Рабочие заказы и позиции при удалении услуги не удаляются.

Поиск использует `LIKE @search ESCAPE N'~'`. Значение поиска передаётся отдельно от SQL; символы %, _ и [ экранируются и ищутся буквально. Условия фильтрации соединяются через AND. min_price и max_price валидируются и передаются как DECIMAL(10,2). Неверный диапазон, повторённый числовой параметр или объект вместо строки возвращают 422. Нет совпадений → 200 и `[]`.

PUT остаётся полным обновлением редактируемых полей и требует название, тип и цену; PATCH допускает любое непустое подмножество этих полей.

## Проверки

`npm test` — 4 автоматических теста, включая сохранность неприсланных полей и отклонение неправильных PATCH до обращения к репозиторию.

`npm run lab4:check` — 54 HTTP-проверки на реальном SQL Server. Скрипт создаёт три собственные временные услуги, проверяет диапазоны, поиск специальных символов, неправильные данные, PATCH/DELETE/404, затем удаляет свои записи. Исходные услуги сравниваются с состоянием до проверки и сохраняются. Файл `lab4-verification.json` содержит фактические результаты без пароля и cookie.

Дополнительно вручную проверены Swagger и страница «Услуги»: поиск, ошибочный диапазон и сброс фильтров. Все материалы находятся в репозитории проекта.
