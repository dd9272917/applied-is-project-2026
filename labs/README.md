# Лабораторные работы 1 и 2

Тема: АРМ фотоцентра и полиграфических услуг. Стек: Node.js, Express, Microsoft SQL Server, HTML/CSS/JavaScript.

Методичка использует Python и SQLModel. Этот комплект адаптирован к существующему приложению: вместо ORM используются DDL и параметризованные SQL-запросы через `mssql`. Возможность такой замены нужно согласовать с преподавателем.

## Файлы

- `Лабораторная_1.docx`, `Лабораторная_2.docx` — отчёты с ответами на контрольные вопросы. Впишите ФИО и группу, добавьте собственные скриншоты выполнения.
- `ER_фотоцентр.png`, `ER_фотоцентр.drawio` — схема всех девяти таблиц проекта и редактируемый исходник для diagrams.net.
- `sql/01-create-lab.sql` — создание отдельной учебной БД `PhotoCenterLab12`. Скрипт остановится, если такая БД уже существует.
- `sql/02-seed-lab.sql` — по три записи в каждой таблице; повторный запуск на заполненной БД остановится.
- `sql/03-check-lab.sql` — проверка количества записей, ограничений и связей, пример расчёта суммы заказа.

## Выполнение

1. Откройте SQL Server Management Studio и подключитесь к своему серверу.
2. Выполните три SQL-файла по порядку. Они не обращаются к рабочей БД приложения.
3. Сохраните скриншоты таблиц, результатов проверок и диаграммы.
4. Для запуска сайта из корня проекта: `npm install`, настройка `.env` по `.env.example`, `npm start`. Учебные SQL-скрипты предназначены для демонстрации модели данных; подключение работающего сайта менять не требуется.
5. Для Git выполните из корня проекта команды ниже. Создание репозитория, коммит и публикация пока не выполнялись.

```powershell
git init
git branch -M main
git add .
git status
git commit -m "feat: add photocenter lab 1 and 2 materials"
git remote add origin https://github.com/YOUR_LOGIN/applied-is-project-2026.git
git push -u origin main
```

Перед публикацией проверьте список добавленных файлов командой `git status`. Файл `.env`, зависимости и журналы исключены через `.gitignore`. Сначала создайте пустой удалённый репозиторий без автоматически добавленных файлов, чтобы избежать конфликта историй. Замените `YOUR_LOGIN` своим логином.

SQL-файлы подготовлены по `schema.sql`; выполнение на SQL Server в рамках подготовки комплекта не подтверждено. Не используйте исходный `schema.sql` для повторной инициализации рабочей БД: в нём есть удаление таблиц.
